# Architecture

Democyber retains its greeting and Java 17 bytecode target. The local source configured port 8081 and exposed all Actuator endpoints. This project uses the handover's port 8080 and limits Actuator exposure to health, info, and Prometheus. The source contained a credential-shaped exercise declaration, which was excluded from the copied Java file. The Spring Boot 4.0.10 migration uses the supported Spring Framework 7.0 and Tomcat 11 release lines. Democyber uses the modular Spring MVC starter and keeps its existing Actuator health response for Compose readiness. Trivy determines whether each candidate meets the configured vulnerability policy. [Spring Boot 4 system requirements](https://docs.spring.io/spring-boot/4.0/system-requirements.html)

1. GitHub Actions checks out the event SHA with read-only repository permission. The pinned Gitleaks CLI scans history reachable from the event commit with default rules and one synthetic fixture rule. The CLI runs the same checks on Windows and GitHub and lets the project retain only rule, line and commit fields.
2. The Maven Wrapper builds, tests and generates coverage. The verification job exchanges its GitHub OIDC identity for a short-lived, project-scoped SonarQube Cloud token. The token goes directly to the Maven scan step, which waits for the Quality Gate.
3. Docker builds one local candidate. Trivy consumes an archive of that exact image ID, creates a CycloneDX SBOM, and rejects HIGH and CRITICAL findings. The project has no accepted exceptions.
4. Compose starts the scanned candidate on an isolated project network, with application rebuilds and pulls disabled. The runtime check compares the container's image ID to the scanned ID and exercises functional and security assertions. ZAP passively analyzes responses to two fixed GET requests to the disposable app. The policy blocks Medium and High findings and report/tool errors. Low findings remain in the report. The OpenAPI file records the greeting contract. The selected passive approach does not exercise the requested active API Scan coverage. [ZAP Automation Framework](https://www.zaproxy.org/docs/automate/automation-framework/)
5. Prometheus pulls `app:8080/actuator/prometheus`. Grafana queries Prometheus through a provisioned data source. A controlled app stop causes Prometheus to fire `DemocyberDown`, Alertmanager to route it, and the unexposed receiver to record the delivered webhook. The runtime check confirms the app restarts and still uses the scanned image.
6. Successful verification on protected `main` exports the tested image. The publish job validates archive SHA-256, commit, and loaded image ID before using its scoped package token. It pushes the commit tag and records the immutable manifest digest. The registry configuration digest is checked against the SHA-256 of the verified archive configuration. Docker engine image IDs can refer to the configuration or manifest depending on the image store.
